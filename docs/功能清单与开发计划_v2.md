## 2. A. 故障管理

### 业务目标
从故障发生到维修完成再到知识沉淀的完整闭环，缩短 MTTR，提升维修质量。

### 功能列表

| 编号 | 功能 | 描述 | 状态 | 涉及页面/API | 优先级 |
|------|------|------|------|-------------|--------|
| A-01 | **设备状态全景看板** | 所有设备运行状态可视化（运行/待机/换型/故障/保养/检修/报废），状态汇总统计 | ✅ 已实现 | DeviceList.tsx, devices API | P0 |
| A-02 | **设备详情与状态时间线** | 单设备基本信息、健康度、OEE、MTBF/MTTR、关联工单 | ✅ 已实现 | DeviceDetail.tsx | P0 |
| A-03 | **状态规则引擎** | 自定义状态切换规则、分组聚合、状态变更自动通知 | ❌ 待开发 | 新 API + 页面 | P2 |
| A-04 | **AI 异常检测** | IoT 数据实时异常检测，自动标记告警 | ❌ 待开发 | IoT 接入 + AI 模型 | P3 |
| A-05 | **多端故障申报** | 扫码报修、语音报修、拍照上报、IoT 自动创建工单 | ✅ 已实现（基础版） | ReportFault.tsx | P0 |
| A-06 | **智能故障分类** | 故障类型树（机械/电气/液压/气动/软件）、优先级 P0-P3、故障码库 | ✅ 已实现 | ReportFault.tsx | P0 |
| A-07 | **工单自动派发** | 基于设备/技能/负载的智能派单、未接单升级 | ⚠️ 部分实现（手动接单） | WorkOrderDetail.tsx | P1 |
| A-08 | **报修信息模板** | 结构化表单、动态字段、历史关联 | ✅ 已实现 | ReportFault.tsx | P0 |
| A-09 | **维修工单全流程** | 接单→诊断→维修→验证→完成→评价 全流程管理 | ✅ 已实现 | WorkOrderDetail.tsx, WorkOrderList.tsx | P0 |
| A-10 | **AI 辅助诊断** | 相似案例匹配、诊断方案推荐、备件预检 | ✅ 已实现（Mock） | WorkOrderDetail AI Modal | P0 |
| A-11 | **根因分析 RCA** | 5-Why 分析引导、鱼骨图、帕累托、改善建议 | ❌ 待开发 | 新页面 + API | P1 |
| A-12 | **维修知识沉淀** | 完工后自动生成知识条目、审核后入库 | ✅ 已实现 | KnowledgeBase.tsx, workOrders complete API | P0 |

### 待开发详情

#### A-03 状态规则引擎
- **后端**: 新建 `status-rules` API（CRUD），规则模型 { trigger: '连续N次报警' / '超过N分钟未响应', action: '自动切换状态' / '通知主管', target: '设备' / '产线' }
- **前端**: 规则配置页面（表格 + 编辑弹窗），状态聚合组件（产线 → 车间 → 工厂）
- **验收**: 可配置 ≥ 3 种规则；状态变更通知延迟 ≤ 3s

#### A-07 智能派单
- **后端**: 在 workOrders API 增加 `auto-dispatch` 端点，基于设备类型匹配技能矩阵
- **前端**: 工单详情显示"推荐维修人"，主管可确认派单
- **验收**: 自动推荐准确率 ≥ 80%

#### A-11 根因分析 RCA
- **后端**: `work-orders/:id/rca` API，引导 5-Why 问答；`work-orders/:id/fishbone` API 生成鱼骨图数据
- **前端**: RCA 页面（5-Why 逐步引导组件 + 鱼骨图 ECharts）
- **验收**: 支持 5 层 Why 追问；鱼骨图覆盖 6 个维度

## 3. B. 预防管理

### 业务目标
通过标准化的点检/保养体系和 AI 预测，实现"防患于未然"，降低非计划停机。

### 功能列表

| 编号 | 功能 | 描述 | 状态 | 涉及页面/API | 优先级 |
|------|------|------|------|-------------|--------|
| B-01 | **点检标准管理** | 点检层级定义（日/周/月/季度）、点检项目库、标准范围、SOP 关联 | ⚠️ 部分实现（预设数据） | InspectionPage.tsx | P0 |
| B-02 | **移动端点检执行** | 扫码点检、数值/布尔/拍照录入、异常自动创建工单、防漏检提醒 | ✅ 已实现 | InspectionPage.tsx | P0 |
| B-03 | **点检计划与排程** | 自动排程、日历视图、批量排程、频率动态调整 | ❌ 待开发 | InspectionPlan 新页面 | P1 |
| B-04 | **点检数据分析** | 完成率统计、异常趋势、质量评估、健康度关联 | ❌ 待开发 | InspectionAnalysis 新页面 | P1 |
| B-05 | **AI 智能点检优化** | 异常点检项预测、频率优化、标准优化 | ❌ 待开发 | AI 增强层 | P2 |
| B-06 | **保养计划管理** | 保养类型（日常/一级/二级/大修）、触发方式（时间/运行时长/产量） | ❌ 待开发 | MaintenancePlan 新页面 + API | P0 |
| B-07 | **保养执行与记录** | 扫码启动保养、SOP 指引、步骒记录、备件更换、完工确认 | ❌ 待开发 | MaintenanceExecute 新页面 | P0 |
| B-08 | **保养分析** | 保养计划执行率、延期率、保养质量评分、保养与故障关联分析 | ❌ 待开发 | MaintenanceAnalysis 新页面 | P1 |
| B-09 | **AI 预测性保养** | 基于健康度/历史故障/运行数据智能推荐保养时机 | ❌ 待开发 | AI 增强层 + 现有 API | P2 |

### 待开发详情

#### B-01 点检标准管理（升级）
- **后端**: 新增 `inspection-plans` API（CRUD），模型包含 { deviceType, level, items[], frequency, sopUrl }
- **前端**: 点检标准配置页面（表格 + 编辑弹窗），支持按设备类型预设
- **迁移**: 将 InspectionPage 中的 presetItems 改为从 API 动态获取

#### B-03 点检计划与排程
- **后端**: `inspection-plans/schedule` API，自动生成每日/每周点检任务列表
- **前端**: 日历视图（@fullcalendar/react），显示全厂点检任务，支持拖拽调整
- **验收**: 排程自动生成准确率 100%；支持拖拽调整

#### B-06 保养计划管理
- **后端**: 新增 `maintenance` 模型 + API（CRUD），字段：{ deviceId, type, triggerType, triggerValue, intervalDays, items[], createdAt }
- **前端**: 保养计划列表页（Table）+ 编辑 Modal，按设备/类型筛选
- **验收**: 支持 3 种触发方式；到期自动提醒

#### B-07 保养执行与记录
- **后端**: `maintenance/:id/execute` API，记录保养步骤、耗时、更换备件
- **前端**: 保养执行页面（扫码启动 → 步骤列表 → 结果确认 → 完工评价）
- **验收**: 保养记录完整可追溯

## 4. C. 效率管理

### 业务目标
量化 OEE、识别六大损失、驱动持续改善，形成"识别 → 分析 → 改善 → 验证"闭环。

### 功能列表

| 编号 | 功能 | 描述 | 状态 | 涉及页面/API | 优先级 |
|------|------|------|------|-------------|--------|
| C-01 | **OEE 实时计算与展示** | OEE = 可用率 × 性能率 × 质量率，实时计算，设备级/产线级/工厂级汇总 | ✅ 已实现 | OEEDashboard.tsx, dashboard/oee API | P0 |
| C-02 | **六大损失可视化** | 设备故障/换型/短暂停机/速度降低/废品/启动损失 图表展示 | ✅ 已实现 | OEEDashboard.tsx, dashboard/losses API | P0 |
| C-03 | **损失追踪与归因** | 停机原因代码记录、多级分类、自动关联生产/保养数据 | ❌ 待开发 | 新 API + OEE 详情页扩展 | P1 |
| C-04 | **损失趋势与对比** | 日/周/月趋势、设备/班组/产线对比、改善前后对比、行业基准 | ✅ 已实现（基础版） | OEEDashboard trend chart | P1 |
| C-05 | **帕累托分析** | TOP 损失原因识别（80/20 法则），多维分析（设备/班组/产品） | ✅ 已实现 | LossAnalysis.tsx, dashboard/pareto API | P0 |
| C-06 | **根本原因分析工具** | 时间序列分析、关联分析、趋势预测 | ❌ 待开发 | LossAnalysis 扩展 | P2 |
| C-07 | **改善项目管理** | 创建→跟踪→评估→标准化 闭环管理 | ✅ 已实现 | ImprovementProjects.tsx | P0 |
| C-08 | **效率看板（Andon）** | 车间实时看板、移动端看板、异常推送、交接班报告 | ❌ 待开发 | AndonBoard 新页面 | P1 |

### 待开发详情

#### C-03 损失追踪与归因
- **后端**: `loss-records` API（CRUD），模型 { deviceId, type, causeCode, startAt, endAt, duration, relatedWoId, relatedProdId }
- **前端**: OEE 详情 Drill-down：点击损失类型 → 显示该类型所有事件列表 → 点击事件查看详情
- **验收**: 每次停机/异常可追踪到原因代码

#### C-08 效率看板
- **后端**: `dashboard/andon` API，返回实时汇总数据
- **前端**: 看板页面（大屏模式），展示 OEE 实时值、各设备状态灯、最近告警
- **验收**: 数据 10s 内刷新；可切换全屏/大屏模式

|------|------|------|------|-------------|--------|

| D-02 | **工治具状态管理** | 在库/在用/保养/维修/报废/待检 状态定义与切换、操作记录 | ❌ 待开发 | ToolingList.tsx（状态标签 + 切换操作） | P0 |
| D-03 | **领用/归还流程** | 扫码领用→绑定设备→归还→超期提醒 | ❌ 待开发 | ToolingCheckout 页面 | P1 |
| D-04 | **工治具使用跟踪** | 每次使用的设备/产品/时长/操作员记录、异常记录 | ❌ 待开发 | 领用归还 API 扩展 | P1 |
| D-05 | **工治具保养管理** | 基于使用次数/时长的保养计划、保养项目标准化、履历记录 | ❌ 待开发 | ToolingMaintenance 页面 | P1 |
| D-06 | **库存管理** | 安全库存预警、盘点、周转率分析 | ❌ 待开发 | ToolingInventory 页面 | P2 |
| D-07 | **寿命模型** | 理论寿命设定、实际寿命追踪、衰减曲线 | ❌ 待开发 | ToolingLife API + 页面 | P1 |

- **后端**: `toolings/:id/status` PUT API，自动记录操作日志

- **前端**: ToolingDetail 显示寿命仪表盘（剩余寿命 % + 预计可用天数）

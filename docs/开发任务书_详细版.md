## 一、任务编码规则

每个任务 ID 格式：`{Phase}-{Track}.{Number}`

| 前缀 | 含义 |
|------|------|
| **DS** | Demo Sprint |
| **MVP** | Phase 1: MVP |
| **AI** | Phase 2: V1.0 AI 增强 |
| **OPT** | Phase 3: V2.0 智能优化 |

### 优先级标记

| 标记 | 含义 | 动作 |
|:----:|------|------|
| **P0** | 阻塞性 | 不做这个，后面的任务都动不了 |
| **P1** | 核心功能 | 不做这个，用户旅程走不通 |
| **P2** | 增强体验 | 做了更好，不做也不影响核心流程 |
| **P3** | 锦上添花 | 有时间再做 |

### 角色标记

| 标记 | 含义 |
|:----:|------|
| **FE** | Frontend（前端） |
| **BE** | Backend（后端） |
| **FS** | Fullstack（全栈） |
| **DS** | Design（设计） |
| **AI** | AI/ML（算法） |

    │
    │  交付: 可演示的原型 + Mock 数据
    │
    ▼

    │
    │  前置条件: Phase 0 的 API 架构 + 前端框架
    │  交付: 可上线的系统 + 真实 IoT 数据
    │
    ▼

    │
    │  前置条件: Phase 1 的 1 个月 IoT 数据 + 50+ 真实工单

    │
    ▼

    ▼

### 6.3 关键路径风险点

| 风险点 | 影响 | 备选方案 |
|--------|------|---------|
| Docker Compose 环境不一致 | Day 1 阻塞，后续全阻塞 | 准备一个预装环境的 VM 镜像 |
| 移动端响应式布局调试耗时 | Day 3-4 阻塞 | 先用 Chrome DevTools 模拟，最后统一调 |
| AI 诊断 Mock 接口前端对接 | Day 6 部分阻塞 | FE 可以先硬编码 JSON 在本地开发 |
| 3 条旅程端到端联调 | Day 13 集中爆发 | 每天结束时做一次端到端验证 |
